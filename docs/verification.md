## ตรวจโค้ดอิสระและการแก้ไข

ผู้ตรวจอิสระตรวจ source แบบ read-only และไม่แก้ฐานข้อมูล พบเรื่องสำคัญสองเรื่อง:

1. คืนสต็อกเกินขนาด INT ตอนยกเลิกบิล: เพิ่ม validation ภายใต้ product lock และ rollback
   มี regression test ที่ล้มเหลวก่อนแก้และผ่านหลังแก้
2. old input ที่ผิดชนิดเป็น array ทำให้ e() แสดงหน้าไม่ได้: เพิ่ม FormValue สำหรับค่าฟอร์ม scalar
   ทดสอบ POST ข้อมูลผิดชนิดและ GET หน้าฟอร์มซ้ำทั้งหน้าขายและลูกค้า ผ่านแล้ว

พบตะกร้าที่ใช้คีย์ไม่ต่อเนื่องถูก encode เป็น JSON object แล้วหายเมื่อส่งฟอร์มผิดพลาด
จัดเป็นปัญหาที่ต้องแก้ตามข้อกำหนดรักษาตะกร้า เพิ่ม array_values ก่อน encode และทดสอบผ่าน
ไม่มีข้อ Critical และไม่มี Minor ที่ค้างหลังประเมินระดับความสำคัญ

## ข้อตัดสินใจและผลที่ต้องทราบ

1. โฟลเดอร์ไม่มี Git จึงทำในโฟลเดอร์เดิมตามที่อนุมัติ ไม่สร้าง repository หรือ worktree
   เก็บ ledger และผลตรวจไว้ใน docs แทนประวัติ commit: ไม่มี automatic Git rollback
2. แบ่ง CheckoutRules ให้ request และ service ใช้ validation ชุดเดียวกัน เพื่อไม่ให้กฎต่างกัน:
   เพิ่มคลาสเล็กหนึ่งไฟล์ ไม่เพิ่ม dependency
3. ยกระดับปัญหาคีย์ตะกร้าเป็นเรื่องต้องแก้ เพราะข้อมูลที่รับได้ไม่ควรหายเมื่อเงินไม่พอ:
   เพิ่มการจัดคีย์เพียงขั้นเดียว ไม่มีการแก้ยอดหรือข้อมูลขาย
4. ตรวจลำดับ locks/unique constraints และทดสอบ idempotency/rollback ด้วย SQLite แล้ว
   แต่ยังไม่ได้ stress test MySQL ด้วยหลาย client พร้อมกัน: หากใช้งานหลายเครื่องควรทดสอบ
   contention/retry เพิ่มก่อนใช้งานระดับนั้น
5. ผู้พัฒนาตรวจหน้าเว็บและ provisioning แทนหัวข้อที่ผู้ตรวจแยกไว้ตามขอบเขตหน้าที่:
   เครื่องพิมพ์จริงอาจต้องปรับการตั้งค่ากระดาษเพิ่มเติม

ไม่มีการ merge, push, สร้าง PR หรือ deploy เพราะเป็นโฟลเดอร์โปรเจกต์ท้องถิ่นที่ไม่มี Git
เก็บ source, แบบระบบ, แผน, ledger และ database backups ไว้ครบ
